Dual routing: Zoho for transactional mail (registration, password reset). Resend for bulk/alert mail (saved search alerts, spam notifications). Routing determined by email type in core/emails.py.

Railway-hosted n8n instance. Receives webhook POST from Django when a new listing is approved. Workflow posts to Facebook Page + Instagram. 60-second delay allows images to upload first.

One-click Google sign-in via @react-oauth/google on frontend. Token sent to /api/users/auth/google/ → dj-rest-auth social adapter creates/links User account and returns JWT pair.

Key Data Flows
Auth Flow — JWT + Cookie
1
Login
POST /api/auth/login/ → Django returns access (JSON) + sets refresh token as httpOnly SameSite=Lax cookie.
2
Access token stored
Frontend stores access token in sessionStorage (tab-scoped). Zustand stores user object (is_staff/is_superuser stripped).
3
API calls
axios interceptor reads token from sessionStorage → Authorization: Bearer header on every request.
4
Silent refresh
New tab: no sessionStorage token → POST /token/refresh/ withCredentials → cookie auto-sent → new access token.
Listing Creation — Two-Step
1
Base listing
POST /api/listings/create/ → creates Listing (job/room/event/notice). 5-min cooldown + 24h dupe title check (excludes soft-deleted).
2
Type detail
POST /api/jobs/create/ (or rooms/events/notices) → attaches type-specific record to the Listing. Rollback soft-deletes base on failure.
3
Image upload
POST /api/listings/{slug}/images/ — separate request after listing created. Up to 5 images per listing.
4
Side effects
Background threads: IndexNow ping, n8n webhook (60s delay), geocoding, saved search alert emails, spam duplicate check.
WebSocket Messaging
1
Request ticket
POST /api/messages/ws-ticket/ with Bearer token → Django generates UUID, stores in Redis with ws_ticket:{uuid} key (30s TTL).
2
Open WebSocket
wss://…/ws/messages/{id}/?ticket={uuid} — JWT never in URL. JWTWebsocketMiddleware reads ticket from cache, deletes it (one-time use).
3
Real-time messages
Django Channels consumer broadcasts via Redis pub/sub. Messages persisted to DB. Banned users get 403 on REST send.
Featured Listing — Payment
1
Initiate checkout
POST /api/payments/feature/{id}/ → creates Stripe Checkout Session, returns session URL. Frontend redirects user.
2
Stripe processes
User completes payment on Stripe hosted page → redirected to /payment/success or /payment/cancel.
3
Webhook confirms
POST /api/payments/webhook/ → Stripe sends payment_intent.succeeded → listing.is_featured = True, FeaturedPayment created.
4
Invoice
GET /api/payments/invoice/{id}/ → WeasyPrint renders PDF invoice with full-width dark header (Wardiere-style layout).
Database Design

PostgreSQL (Railway managed). Django ORM with migrations. All timestamps use auto_now_add / auto_now. Soft-delete pattern on Listing (is_deleted flag, never hard-deleted). Slugs auto-generated from title via python-slugify + uniqueness loop.

Indexing & Query Patterns
Implicit indexes
All PKs and FK columns. unique=True fields (slug, email). unique_together constraints (e.g. SavedListing, JobApplication). M2M junction tables get two FK indexes.
Ordering & range queries
Most list views order by -updated_at. Sitemap queries also on -updated_at. Conversation list orders by -last_message_at (denormalized for performance).
Soft delete pattern
Listing.is_deleted flag. All public list views filter .filter(is_deleted=False). Duplicate-title dupe check also excludes deleted. Hard delete only via admin or account deletion transaction.
N+1 guards
List serializers use select_related for FK (user, listing) and prefetch_related for M2M (images, upvotes, participants). Detail views include nested serializers for images and type detail in one query.
Atomic operations
PollVote swap: transaction.atomic() delete old → create new prevents double-voting race. PointEvent uses F() expression update to avoid read-modify-write race on User.points.
Full-text search
Global search via icontains across title/description per listing type. No dedicated FTS index currently — candidate for SearchVectorField if query volume grows.

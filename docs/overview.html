What is NepSaathi

NepSaathi ("Nep" = Nepali, "Saathi" = friend) is a community marketplace and resource hub built specifically for Nepalese people living in Australia. Think of it as Gumtree meets a community forum, tailored entirely for the Nepali diaspora.

The platform solves a real gap: Nepalese Australians previously had to rely on scattered Facebook groups, WhatsApp chains, and generic classifieds sites to find jobs, accommodation, connect with local businesses, and share information. NepSaathi brings all of that into one trusted, community-first space.

Who it's for

New arrivals
People who just moved to Australia looking for accommodation, jobs, and community connections.
Established community
Nepalese Australians posting jobs, renting rooms, advertising events, and running businesses.
Business owners
Nepali restaurant owners, travel agents, migration agents, and other service providers.
Anyone sending money
Nepalese Australians who regularly transfer money back home to Nepal.

How to Access

The site

Everything is at nepsaathi.com. No app to install — it works in any browser, and there is a PWA (Progressive Web App) install prompt so users can add it to their home screen.

Without an account

Anyone can browse the site without logging in:

You can view all listings (jobs, rooms, events, notices), browse businesses and reviews, read all forum posts and replies, use the Send Money rate comparator, and see live exchange rates — no account needed.

The only things hidden from guests are: the listing owner's phone/WhatsApp number and email (shown as "Sign in to view contact details").

Creating an account

1
Go to /register
Enter your first name, last name, email, and password. Or click "Continue with Google" for one-click signup via Google OAuth.
2
Verify your email
A verification link is sent immediately. Google OAuth accounts are auto-verified — no email step needed.
3
Fully unlocked
Post listings, message other users, RSVP to events, write business reviews, create forum posts, and save search alerts.

Auth tokens

Login issues JWT tokens — a short-lived access token (60 min) and a long-lived refresh token (7 days). The frontend auto-refreshes silently when the access token expires. Logging out blacklists the refresh token so it can't be reused.

How posting a listing works (2-step)

Every listing is a 2-step create: first a base Listing record is created (title, description, location, contact), then the type-specific details (e.g. Job: salary, company) are attached to it. This keeps the data model clean and lets all listings share common fields.
1
Fill the base form at /post-ad
Title, description, location (with Nominatim suburb autocomplete), state, contact details. The ✨ Improve with AI button rewrites the description via Groq Llama 3 (5 uses/day). A base Listing record is created and returns an ID.
2
Type-specific details are attached
Using the listing ID, the form posts job/room/event/notice-specific fields. The listing is now complete and goes live.
3
Spam check runs in background
A background thread checks for duplicate phone numbers + similar titles, or near-identical descriptions. If flagged, the listing is set to "under review" and admin is notified by email.
4
Saved search alerts fire
Any user who has a saved search matching this listing's type and filters gets an email alert immediately.

Listing lifecycle

Business Directory

Businesses are completely separate from listings — they have their own lifecycle, images, and reviews. They don't expire. A business profile is a permanent presence on the platform.

1
Register a business at /register-business
Business name, category (14 options: restaurant, grocery, legal, migration, etc.), suburb, state, contact details, operating hours. Up to 5 images.
2
Community can leave reviews
Anyone logged in can leave a star rating (1–5) and comment. One review per user. Business owners cannot review their own business.
3
Admin can verify
Verified businesses get a badge. Verification is admin-only and done manually to ensure trust.
Max 5 businesses per user. Duplicate name + state is blocked at registration. ABN is stored privately and never shown publicly.

Community Forum

The forum is a community discussion board at /forum. Posts are organized into 6 topic categories:

Visa & Immigration Accommodation Jobs & Work Events Business General

Anyone can read posts. Logged-in users can create posts, reply, and upvote both posts and replies. Posts can optionally include a poll (2–4 options, one vote per user). Posts can be pinned by admins and closed to prevent further replies.

The ✨ Improve with AI button on the create form rewrites the post body for clarity and grammar via Groq Llama 3 — shared 5/day limit with the listing AI improve.

Every new forum post triggers an IndexNow ping to Bing so it gets indexed by search engines within minutes — good for SEO without any manual effort.

Messaging

1-to-1 conversations between users, typically started from a listing page. At /messages.

1
User clicks "Message" on a listing
The "Get in Touch" section on every listing and business detail page has a Message button. Clicking it opens a pre-filled message dialog.
2
Conversation is created (or resumed)
If a conversation already exists between these two users about this listing, it resumes. Otherwise a new conversation is created and the message is sent.
3
Real-time via WebSocket
Once in a conversation, new messages appear instantly without refreshing — powered by Django Channels over ASGI. The connection pings every 10 seconds to stay alive on Railway's proxy.
4
Notifications fire
The recipient gets a browser push notification (if subscribed) and sees an unread badge on the navbar. If they're already on the site but not on the messages page, a toast notification appears.

Conversations are soft-deleted (hidden, not removed) — each user can hide a conversation from their inbox independently without the other party losing their history.

Send Money Comparator

At /send-money — no login required. Compares live AUD → NPR rates across Wise, Remitly, WorldRemit, and Western Union.

1
Cron fetches mid-market rate every run
The fetch_remittance_rates command pulls the live AUD→NPR mid-market rate from open.er-api.com (free, no API key needed).
2
Provider rates are derived
Each provider's typical margin is applied to the mid-market rate: Wise ~0.55%, Remitly ~1.2%, WorldRemit ~1.8%, Western Union ~3.5%. Stored in the database.
3
User enters an amount and compares
The page shows a table sorted by "most NPR received". User types an AUD amount, the table updates instantly client-side. Each row has a "Send now →" link to the provider's site.

Featured Listings & Payments

Listing owners can pay a small fee to have their listing shown as "Featured" — pinned to the top of the relevant page and shown in the Featured carousel on the homepage. Only job/room/event/notice listings can be featured (not businesses).

1
Owner clicks "Feature this listing" from My Listings
A Stripe Checkout session is created. The owner is redirected to Stripe's hosted payment page.
2
Payment completes on Stripe
Stripe fires a webhook to the backend. The webhook verifies the signature, marks payment as completed, and sets is_featured = True on the listing.
3
Invoice emailed with PDF attachment
A GST-compliant PDF invoice is generated and emailed to the owner. It's also downloadable any time from My Listings.

Cron Jobs — What Runs Automatically

A separate Railway service runs cron.sh on a schedule. Each command is independent — if one fails, the others still run.

expire_listings
Finds all active listings past their 30-day expiry and sets their status to expired. They disappear from the site but are not deleted.
expire_featured_businesses
Clears the is_featured flag on businesses whose featured period has ended.
send_expiry_warnings
Finds listings expiring within 4 days that haven't had a warning sent yet. Sends email + push notification to the owner. The 4-day window means it catches up if the cron missed a day.
send_event_reminders
Finds events happening within the next 24 hours. Sends a reminder email to every user who RSVPed.
fetch_remittance_rates
Fetches the live AUD→NPR mid-market rate and updates all 4 provider rows in the database. The /send-money page always shows the most recently fetched rates.

Push Notifications & Real-time

Browser push notifications

When a logged-in user first visits, the browser asks for notification permission. If granted, a VAPID-based push subscription is registered with the server. Push is sent for:

New message received Listing expiring soon Event reminder

WebSocket (real-time chat)

Each conversation has a live WebSocket channel. When one user sends a message:

1
REST API saves the message to the database
POST /api/messages/<id>/send/ — the message is persisted first.
2
Django Channels broadcasts over WebSocket
The message is pushed to the other participant's open connection instantly — no polling.
3
Push notification fires if other user is not in the conversation
If the recipient's browser isn't in that conversation tab, they get a push notification.

Navbar unread badge

The message icon in the navbar polls for an unread count every 30 seconds. If the count increases while the user is on any other page, a toast notification pops up with a link to the inbox.

Admin & Moderation

Accessing admin

The Django admin panel is at a non-standard URL (obscured for security). Only staff + superuser accounts can access it. From the frontend, superusers also have access to /panel — a dashboard showing site-wide stats, revenue, reports, and recent activity.

Listing reports

1
User reports a listing
Reason: spam / fake / inappropriate / scam / wrong category / other. The listing gets an is_under_review flag and admin is emailed.
2
Admin reviews in the Django admin
Can take a "Clear listing" action (approve it — removes the under-review flag) or a "Remove listing" action (deletes it and emails the owner).
3
Auto-ban after 3 removals
If an owner's listings are removed for violations 3 times, they are automatically banned. A ban notification email is sent.

Featured listing approvals

Featured listings are managed through the Payments admin. Stripe's webhook handles activation automatically — no manual step needed.

Business verification

Admin manually sets is_verified=True on businesses after checking legitimacy. Verified businesses show a badge on their profile.

Forum moderation

Admins can pin posts, close threads (no more replies), delete any post or reply. The admin panel has inline replies shown under each post for quick review.

The backend runs as an ASGI application (uvicorn workers inside gunicorn) — this is required for Django Channels WebSocket support. Both the REST API and WebSocket connections go through the same process.

Key design decisions

Listings are polymorphic
A base Listing model holds all shared fields. Job/Room/Event/Notice each have a OneToOne relationship to it, holding only their specific fields. This keeps search, filtering, and reporting unified.
Businesses are completely separate
The Business model is independent — not linked to Listing. This gives businesses their own lifecycle (no expiry), their own images, and their own review system.
All emails are non-blocking
Every email function fires in a daemon thread so the API response is never delayed by email sending. If the email fails, it's logged but the user's action succeeds.
Token refresh without race conditions
The frontend axios interceptor queues all concurrent 401 responses, refreshes the token once, then replays every queued request. Multiple tabs can't trigger multiple simultaneous refreshes.

AI Features (Groq + Llama 3)

NepSaathi uses the Groq API with llama-3.1-8b-instant (free tier: 14,400 req/day) for AI writing assistance. The API key lives only on the backend — never exposed to the frontend.

FeatureWhereEndpointWhat it does
Listing description improvePost Ad formPOST /api/listings/ai-improve/Rewrites rough description into clear, professional listing copy. Knows listing type, location, salary/price.
Forum post improveForum create formPOST /api/forum/ai-improve/Rewrites forum post body for clarity and grammar. Knows category and title.
Both endpoints share the same throttle scope ai_improve — 5 uses per user per day across both features combined. DRF's ScopedRateThrottle enforces this with a single counter per user.

New listings (last 24 hours)

The homepage shows a "New today" carousel (green-themed, same pattern as the Featured carousel) that only appears when listings were posted in the last 24 hours. Clicking "View all new listings" goes to /new-listings — a full page with type/state filters and pagination.

Backend: GET /api/listings/?new=true filters by created_at__gte=now()-24h. All listing cards site-wide also show a green NEW badge on posts under 24 hours old.

Deployment

FrontendVercel — auto-deploys on push to main. SPA rewrite sends all routes to index.html.
Backend APIRailway — gunicorn with 4 UvicornWorkers. Runs migrations on every deploy via start.sh.
Cron serviceSeparate Railway service runs cron.sh. Note: Railway doesn't always detect cron.sh changes — may need a manual redeploy.
Forum sitemapDjango serves a live forum sitemap at /api/sitemap-forum.xml, proxied via Vercel to nepsaathi.com/sitemap-forum.xml for Google Search Console.
MediaAll images go to Cloudinary. Local dev uses a local /media/ folder.
After any deployMigrations run automatically. If new remittance/cron features were added, also run fetch_remittance_rates to seed fresh data.
The single point of failure is PostgreSQL. If the database goes down, everything goes down. Every other service (Cloudinary, Stripe, Resend, the exchange rate API) degrades gracefully — the affected feature fails but the rest of the site keeps working.

Getting Started

Create an account

1
Go to /register
Enter first name, last name, email and a password. Or click Continue with Google for instant one-click signup.
2
Verify your email
Check your inbox for a verification link. Google OAuth accounts are auto-verified — no email step needed.
3
Complete your profile
Go to Profile to add your photo, phone, location, and a short bio. A full profile builds trust with other members.
📸Screenshot: Register page — email form + Google sign-in button

Referral bonus

If a friend invited you, use their referral link or append ?ref=THEIR_CODE to the register URL. Both of you earn bonus points on successful signup.

Auth tokens

Login issues a 60-minute access token and 7-day refresh token. The frontend refreshes silently when the access token expires. Logging out blacklists the refresh token so it cannot be reused.

📢

Post an Ad

All listings follow a multi-step wizard. You can post up to 20 active listings at a time, and must wait 5 minutes between posts.

Step 1 — Choose listing type

Job
Offering a vacancy — or tick "I'm looking for work" to post as a job seeker.
Room
Renting out a room — or tick "I'm seeking accommodation".
Event
Promoting a cultural, sports, food, religious or community event.
Notice
Classifieds: items for sale, services, lost & found, general announcements.
💡
Wanted listings (I'm looking for…) skip the photo upload step and go live immediately after you fill in the details.

Step 2 — Basic details

Title, description, location (suburb autocomplete via OpenStreetMap), state, and contact details. The ✨ Improve with AI button rewrites your description professionally — you'll see a purple preview box to accept or discard.

📸Screenshot: AI improve preview box with "Use this" and "Discard" buttons

Step 3 — Type-specific details

Salary range for jobs · rent/week and bond for rooms · date and venue for events · price and condition for notices.

Step 4 — Add photos (offering listings only)

Upload up to 5 photos, max 5 MB each. Drag-and-drop or click to select. Wanted/seeking listings skip this step entirely.

⚠️
A live countdown timer appears in amber if you try to post within 5 minutes of your last listing. Submit buttons are disabled until it reaches zero. The 10/hour rate limit shows a separate longer countdown.

What is NepSaathi

NepSaathi ("Nep" = Nepali, "Saathi" = friend) is a community marketplace built for Nepalese people living in Australia. Think Gumtree meets a community forum, tailored for the Nepali diaspora.

Two-step listing create

1
POST /api/listings/create/
Creates the base Listing row (title, description, type, location, contact). Returns a listing.id.
2
POST /api/jobs|rooms|events|notices/create/
Creates the type-specific detail row linked to the listing ID. This keeps shared fields unified and type-specific fields separate.

SilentJWTAuthentication

core/authentication.py — extends JWTAuthentication but returns None instead of raising 401 on expired or invalid tokens. Set as DEFAULT_AUTHENTICATION_CLASSES. Without this, users with stale access tokens in localStorage would see 401 errors on public listing pages.

Key patterns summary

Soft deletesListings → status='deleted'; Businesses → is_active=False; Community posts → is_active=False. Nothing is hard-deleted.
Dual emailResend API in production (Railway); Zoho SMTP in local dev. All emails fire in daemon threads — never block the response.
Token refresh queueAxios interceptor queues concurrent 401s, refreshes once, replays all. Prevents race conditions from multiple tabs.
WebSocket keep-aliveClient pings every 10 s — Railway proxy closes idle WS connections without it.
Nominatim geocodingBackground thread resolves listing location → lat/lng after creation. Used by map view.
SavedSearch alertsOn listing creation, background thread emails all users whose saved search filters match.
Max active listings20 per user (enforced in listings/views.py; old docstring said 10 — code is the truth).
Panel security4-layer: IsSuperUser DRF permission → "Not found." to anyone else; SuperUserRoute in React → NotFoundPage; no UI links; not in sitemap.

Key Patterns

Countdown timer for posting cooldown

Backend returns {"cooldown": seconds_remaining} (not a plain error string) when the 5-minute cooldown is hit. Frontend stores seconds in a useRef, runs setInterval decrementing each second, renders MM:SS in an amber banner, and disables submit buttons until zero. DRF's 429 response ({"detail": "… in N seconds."}) is also parsed via regex /(\d+) seconds?/ and fed to the same countdown.

Django lazy querysets & try/except

A try/except around .filter() or .exclude() does not catch DB errors — SQL runs lazily at serialization time, outside the block. Always evaluate inside the try: qs.first() or list(qs).

Django admin bulk actions bypass save_model

Bulk queryset.update() skips save_model. Any side effects in save_model (e.g. auto-marking reports reviewed) must be duplicated explicitly in each bulk action.

DRF BooleanField in multipart POST

An absent BooleanField in a multipart form POST is received as False — HTML checkbox behaviour. Account for it in serializer defaults and frontend form construction.

React Query gcTime: 0

staleTime: 0 alone still shows cached data while refetching in background. For pages where stale data is harmful (e.g. "under review" banners), also set gcTime: 0 so cache is deleted on unmount and the next visit always fetches fresh.

useToast — correct API

const { addToast } = useToast();   // ✓
// showToast does not exist — fails silently at runtime

is_reported auth gate

get_is_reported() in all serializers returns True only when request.user == obj.user or request.user.is_staff. Anonymous and other authenticated users always receive False. Must be updated in all four type-specific serializers independently.

Prompt injection protection (added 2026-08-10)

User content is wrapped in XML delimiter tags before sending to Groq. The model sometimes echoes them back — strip on return:

# Wrap before sending
prompt = f"...\n\n<user_draft>\n{user_text}\n</user_draft>\n\nRewrite..."

# Strip after receiving
import re as _re
improved = chat.choices[0].message.content.strip()
improved = _re.sub(r'</?user_draft>', '', improved).strip()

Social Media Automation

New listings are automatically posted to the NepSaathi Facebook Page and Instagram Business account via n8n (self-hosted on Railway, Postgres-backed). No manual posting required.

Trigger — listing creation
perform_create in listings/views.py starts a daemon thread. It sleeps 60s (waiting for image uploads to complete), re-fetches the listing with images, then POSTs title / category / location / description / image_url to the n8n webhook. Admin actions (approve_listings, save_model) also fire the webhook when spam-flagged listings are cleared.
n8n workflow — 6 nodes
Webhook → Code (JS) → HTTP Request (Facebook) → IF (image?) → Instagram Create Container → Wait 5s → Instagram Publish

Facebook posts via POST /v26.0/{page_id}/photos (single call, instant).
Instagram requires two calls: /media (create container) → /media_publish. IF node skips Instagram when no image is present.
Dynamic hashtags
Code node builds hashtags per category and state:
• Facebook: 6 tags — 4 core + 2 category-specific
• Instagram: up to 15 — core + full category set + location tags (e.g. #Sydney #SydneyLife for NSW)
Categories: job / room / event / notice / business. States: NSW / VIC / QLD / WA / SA / ACT / TAS / NT.
Tokens & persistence
Permanent Facebook Page token (never expires) stored only in n8n credentials — never in code.
Instagram token requires instagram_content_publish scope; generated via long-lived User Token → Page Token exchange.
n8n data persists in Railway Postgres (DB_TYPE=postgresdb). N8N_ENCRYPTION_KEY env var ensures credentials survive container restarts.
⚠️
Facebook's scraper does not execute JavaScript — React's usePageMeta og:image updates are invisible to the link preview fetcher. Images are sent directly via the url param on the /photos endpoint instead.

Security

AuthJWT rotation + blacklist. 60-min access token, 7-day refresh. Google OAuth with PKCE.
SilentJWTcore/authentication.py returns None on bad token instead of 401 — public pages serve anonymous users cleanly.
Login throttle5/min per IP (rightmost X-Forwarded-For) + 10/period per SHA-256(email[:16]). Both cleared on success.
is_reported gateget_is_reported() returns True only to listing owner or staff. Other auth users receive False — prevents leaking report status.
AI prompt injectionUser content wrapped in XML delimiter tags before Groq call; re.sub strips any echoed tags from response.
HTML injection (emails)All user-supplied strings in email HTML escaped with _h() helper in core/emails.py.
Stripe webhookSignature-verified. select_for_update() prevents duplicate payment processing.
RSVP overbookingselect_for_update() on RSVP creation — concurrent RSVPs cannot exceed max_attendees.
Admin URLObscured path. Returns 404 for wrong guesses.
PanelIsSuperUser returns "Not found." to non-superusers. No UI links. Not in sitemap.
Auto-banOwner auto-banned after 3 admin listing removals for violations.
Contact detailsPhone/WhatsApp/email on listings hidden from unauthenticated users.
HSTS + SSLEnabled when DEBUG=False.

Intentionally deferred

JWT_AUTH_HTTPONLY: False — looks wrong but is correct. Tokens live in localStorage; the dj-rest-auth cookie is never read by the frontend. True fix = full httpOnly cookie migration (not done).

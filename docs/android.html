Android App Documentation

Complete reference for building, signing, and distributing the NepSaathi Android APK. The app wraps the existing React frontend using Capacitor — no separate codebase.

App ID: com.nepsaathi.app Capacitor 8.5.1 Keystore: ~/nepsaathi-release.keystore

Overview

NepSaathi Android is a Capacitor shell wrapping the same React/Vite frontend that runs on the website. There is no separate mobile codebase — all pages, API calls, and state management are shared. The Android project lives in frontend/android/.

Build & Sync

Every time you change frontend code, run the sync script before building the APK in Android Studio.

cd ~/nepsaathi/frontend
npm run cap:sync          # builds React (vite build) then copies dist/ into android/

This is equivalent to npm run build && npx cap sync android. The script is defined in package.json.

Generate APK in Android Studio

  1. Open projectRun npx cap open android from frontend/, or open frontend/android/ directly in Android Studio.
  2. Wait for Gradle syncThe first sync downloads dependencies and takes 2–5 minutes. Watch the bottom status bar.
  3. Debug build (testing only)Build → Build App Bundle(s) / APK(s) → Build APK(s). Output: android/app/build/outputs/apk/debug/app-debug.apk
  4. Release build (Play Store)Build → Generate Signed Bundle / APK → APK → select ~/nepsaathi-release.keystore → alias nepsaathi → select release → Create. Output: android/app/release/nepsaathi-release.apk
⚠️

Do not use the green Run button to generate a release APK — it only builds debug. Always use the Generate Signed APK menu for release builds.

⚠️

Do not delete the adaptive icon XMLs after regeneration — they are needed for the rounded launcher shape on Android 8+. The previous workaround (deleting them) was replaced by providing proper source images to @capacitor/assets.

The generated files land in android/app/src/main/res/mipmap-*/ and drawable-*/. These are checked into git.

CORS Setup

The Android WebView uses https://localhost as its request origin. The Railway Django backend must allow this origin.

Railway environment variable

CORS_ALLOWED_ORIGINS=https://www.nepsaathi.com,https://nepsaathi.com,https://localhost

Set this in the Railway dashboard under the backend service's Variables tab. The app will show a blank screen or "Network Error" without this.

✓

This is already configured in production. Only needed again if the Railway environment is recreated.

Google Login

Google OAuth uses different flows on web vs Android. The GoogleLoginButton.jsx component branches on Capacitor.isNativePlatform().

PlatformLibraryHow it works
Web (browser)@react-oauth/googleOpens a popup window. Returns an access token.
Android (native)@codetrix-studio/capacitor-google-authUses native Google Sign-In SDK. No popup needed.

Both flows send the access token to the Django backend at POST /api/auth/google/ — same endpoint, same user accounts.

Two Android OAuth clients required

Google requires a separate OAuth credential for each signing certificate. You need two Android OAuth clients in Google Cloud Console:

ClientSHA-1 sourceUsed for
Android (debug)Debug keystore at ~/.android/debug.keystoreTesting in Android Studio / development builds
Android (release)Release keystore at ~/nepsaathi-release.keystoreSigned release APK / Play Store

Get SHA-1 fingerprints

# Debug SHA-1
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android | grep SHA1

# Release SHA-1
keytool -list -v -keystore ~/nepsaathi-release.keystore -alias nepsaathi | grep SHA1

Register in Google Cloud Console

  1. Open credentialsAPIs & Services → Credentials → + Create Credentials → OAuth 2.0 Client ID
  2. Set typeApplication type: Android
  3. Fill detailsPackage name: com.nepsaathi.app · SHA-1: paste the fingerprint
  4. Save and waitChanges propagate in ~5 minutes. Test Google login after that.
ℹ️

The serverClientId in capacitor.config.ts is the Web client ID, not the Android client ID. The Android credentials are for verification only. Do not change the serverClientId.

Token Persistence

On the website, the JWT access token is stored in sessionStorage — it clears when the browser tab closes. On Android, sessionStorage clears when the app is killed, which would log users out every time they close the app.

On native (detected via Capacitor.isNativePlatform()), the access token is stored in localStorage instead. This survives app restarts.

StorageWebAndroid
Access tokensessionStorage — clears on tab closelocalStorage — survives app restart
User object + isAuthenticatedlocalStorage via Zustand persist middleware — both platforms
Refresh tokenhttpOnly cookie set by Django backend
⚠️

The httpOnly refresh cookie does not survive app restart on Android due to cross-site cookie restrictions (SameSite=Lax blocks cross-origin requests from https://localhost to Railway). This is why localStorage is used for the access token on native — no cookie refresh needed on startup.

Signing & Keystore

🔑

Never lose the release keystore. If you lose it, you cannot update the app on Play Store — you would have to publish under a new app ID. The keystore is intentionally not committed to git.

PropertyValue
Keystore path~/nepsaathi-release.keystore
Key aliasnepsaathi
APK output pathfrontend/android/app/release/nepsaathi-release.apk
Git trackingExcluded via .gitignore

Create keystore (first time only — already done)

keytool -genkey -v \
  -keystore ~/nepsaathi-release.keystore \
  -alias nepsaathi \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000

Verify keystore integrity

keytool -list -v -keystore ~/nepsaathi-release.keystore -alias nepsaathi
⚠️

Back up the keystore file. Store a copy on an external drive or encrypted cloud storage (e.g. personal Google Drive — not the project repo).

Key Decisions

Why Capacitor and not a native app or React Native?

NepSaathi already had a full-featured React SPA. Capacitor wraps it with near-zero code changes — all pages, API calls, and routing are reused. React Native would require rewriting every component. A fully native app would require a separate codebase. Capacitor was the only option that let us ship in days, not months.

Why does Google login use a different library on Android?

@react-oauth/google uses window.open() to open a popup for the OAuth flow. Android WebView blocks popups. @codetrix-studio/capacitor-google-auth uses the native Google Sign-In SDK which works correctly in a WebView context. The same Django backend endpoint (/api/auth/google/) accepts both.

Why are access tokens in localStorage on Android (not sessionStorage)?

Android kills sessionStorage when the app process is terminated. The httpOnly refresh token cookie also doesn't survive due to SameSite=Lax blocking cross-origin requests from https://localhost to Railway. localStorage persists across app restarts without needing a cookie round-trip.

Why is legacy-peer-deps=true in .npmrc?

@codetrix-studio/capacitor-google-auth@3.4.0-rc.4 declares a peer dependency on @capacitor/core@^6.0.0, but the project uses Capacitor 8.5.1. Without legacy-peer-deps=true, npm ci fails with ERESOLVE. The plugin works correctly at runtime with Capacitor 8.

Why does the APK output name start with "nepsaathi-" not "app-"?

Gradle names the APK after the module folder name ("app") by default. setProperty("archivesBaseName", "nepsaathi") in android/app/build.gradle renames the output to nepsaathi-release.apk.

Why use emoji in BottomNav instead of Phosphor SVG icons?

Phosphor icons are SVG components that render correctly in browsers. On Android WebView, SVG rendering can be inconsistent across devices. Emoji render via the OS font stack and display identically everywhere.

Troubleshooting

Cannot locate tasks that match ':app:unitTestClasses'
Ignore it. This error appears when Android Studio tries to run unit tests. The Capacitor Android project does not include unit tests. Use Build → Generate Signed Bundle/APK instead of the Run button.
npm error code ERESOLVE — could not resolve @capacitor/core@^6.0.0
Fix: Ensure frontend/.npmrc contains legacy-peer-deps=true. This tells npm to skip strict peer dependency resolution.
App icon shows Android robot instead of NepSaathi logo
Fix: Regenerate icons with npx @capacitor/assets generate --iconBackgroundColor=#ffffff --android then sync. The adaptive icon XML files in mipmap-anydpi-v26/ must be present and point to the correct drawable.
Google sign-in shows "access blocked: authorization error"
Fix: The signing certificate's SHA-1 is not registered in Google Cloud Console. Add an Android OAuth credential for the relevant keystore (debug or release). Wait 5 minutes after saving.
Listings not loading — network error / blank page
Fix: Check that https://localhost is in CORS_ALLOWED_ORIGINS on Railway. The Android WebView sends requests from this origin.
User logged out every time app is closed
Fix: Ensure the latest code is built into the APK. The fix stores access tokens in localStorage (not sessionStorage) on native platforms.
npx cap open android — Unable to launch Android Studio
Fix: Android Studio is at /usr/local/android-studio/bin/studio.sh. Run studio.sh directly, or open frontend/android/ manually via File → Open in Android Studio.
